# Architecture

## One core, thin bindings

All behavior is in the Rust core (`core/`). Swift (`MediaLayer/`) and Kotlin (`kotlin/`) contain bindings generated by UniFFI and the typed API generated from your media files. They have no business logic.

## Parts of the core

| Part | Responsibility |
| ---- | -------------- |
| `cache` | One disk cache for all media, budget, eviction strategy, statistics, purge |
| `proxy` | Local HTTP server on 127.0.0.1 for native players, Range requests, playlist rewriting. An origin that answers a Range request with 200 and the whole body is read by one download that streams every range as 206 while it runs and caches the file after the response closes, at any size. An origin that sends no `Content-Length` (chunked, or a CDN that compresses) is stored first, then every range is served from the stored file as 206 with a right `Content-Range` |
| `hls` | Playlist parsing, leading segments, variant choice |
| `prefetch` | Deduplication, queue, priorities, cancel, settled events, the cache strategy of each source ([cache strategies](cache-strategies.md)) |
| `pool` | Pool of native players and its assignment policies (`ring`, `lru`, `pinned`) |
| `session` | Playback arbitration, watchdog, recovery |
| `image` | Image bytes for image loaders: fetch through the core, store in the one disk cache, decode BlurHash |
| `controls` | Limits, statistics, clear, purge, eviction on demand |

`Playlist::parse` parses the base URL and the text once for the response and for prefetch.
The proxy keeps up to 256 plans keyed by namespace and the version of the pinned entry.
`Ledger` counts the memory of the plans. Live playlists use the current TTL.
A version change, purge, clear, a limits change and a restart drop the stored plans.
`Hub` unsubscribe removes the listener by id. Broadcast does not copy the list.
The slot queue takes up to 16 ready commands per `spawn_blocking` and checks the queue before each next command.

## Stall watchdog

While a place plays, the core samples its player and reloads it when the position stops moving. A looping video that wraps to the start counts as moving, so a loop never reloads the player. A video that does not loop and goes back is a stall.

### Recovery state machines

`session/recovery` runs three independent `statig` machines for each loaded source: stall control (`Disarmed`, `Watching`, `Cooling`, `Terminal`), the route chain (`Idle`, `Purging`, `Refreshing`) and the foreground return (`Idle`, `Checking`, `Waiting`). `next_action` feeds one event to all three and returns the one `Action` that the executor must run. A transition only computes the state and the action. Purge, refresh, retry timers and the foreground pass run outside the machine and come back as events of their own load. Attempt counters, retry index and the `WatchdogConfig` stay plain data.

## What the platform provides

| Interface | Purpose |
| --------- | ------- |
| `Fetcher` | Network access: `fetch(request)` returns the status, the headers and a `BodyReader`. `range_start` and `range_end` follow HTTP: both ends are included. Ready-made: `URLSessionFetcher` on Swift, `OkHttpFetcher` on Kotlin |
| `BodyReader` | Reads the body in chunks with `nextChunk()`. The ready-made fetchers read the network into a bounded queue and hand over every byte already received, up to 64 KiB, per call. The core calls `release()` when the body ends or is dropped |
| `SettingsStore` | Local storage for saved limits (read, write, remove a string by key). Ready-made: `UserDefaultsSettings`, `SharedPreferencesSettings` |
| `PlayerSlotFactory` | Creates the native player of a slot. `create` is `async`: it may wait for the native thread |
| `PlayerSlot` | `apply(command)` is `async` and returns after the native player took the `SlotCall` (`load`, `unload`, `preroll`, `play`, `pause`, `mute`, `unmute`, `attach`, `detach`, `seek`, `rate`, `readahead`). The core sends one command at a time per slot. `dispose` is `async` and returns after the native player is destroyed: observers, notifications, view, audio and source are gone, and the thread the slot owns has ended. The core calls it once for every player it created, when the pool shrinks and when the MediaLayer closes. A second `dispose` does nothing and a command after it is ignored. `sample` returns a ready snapshot. `load` carries the generation of the load. `PlaybackRoute` says whether the source is HLS and whether it loops |
| `PlayerEvents` | Player events to the core: `ready`, `visualReady`, `stalled`, `failed`, `ended` (each with the slot and the generation of the load that produced it, the core drops an event of an older load; a delayed step of the recovery, such as a repair, a purge, a retry timer or a watchdog sample, also drops itself when the slot holds another load by the time it finishes), `foreground`, `background`, `memoryWarning`. Get it from `media.playerEvents()`. A flood of events beyond the input limits closes the library with `Overloaded` and tells the observers |
| `DeviceMemory` | Device class in `OpenConfig`: memory size, heap class and the low-memory flag |
| `MemoryReleaser` | `dropMemoryCaches` is called when the system reports critical memory pressure, so Nuke and Coil can drop their memory caches. `shutdown` is `async` and runs once, after every slot is disposed, to end the rest of the platform resources |
| `StatsListener`, `StateListener` | Core notifications: cache statistics and the `MediaState` of one place. `statsStream()` and `stateStream(key:)` wrap them |

## Implementing the platform interfaces

`MediaLayerUI` and its Kotlin twin already contain the fetcher, the settings store, the player slots and the memory signals. Write your own only when you need something different. The settings store is the smallest one.

### Swift

```swift
final class DefaultsSettings: SettingsStore {
  func read(key: String) -> String? { UserDefaults.standard.string(forKey: key) }
  func write(key: String, value: String) { UserDefaults.standard.set(value, forKey: key) }
  func remove(key: String) { UserDefaults.standard.removeObject(forKey: key) }
}
```

### Kotlin

```kotlin
class PrefsSettings(context: Context) : SettingsStore {
  private val prefs = context.getSharedPreferences("medialayer", Context.MODE_PRIVATE)
  override fun read(key: String) = prefs.getString(key, null)
  override fun write(key: String, value: String) = prefs.edit().putString(key, value).apply()
  override fun remove(key: String) = prefs.edit().remove(key).apply()
}
```

## Image loaders

Nuke and Coil keep decoding and memory caching. Their network access goes through the core.

### Swift

```swift
let result = try await media.fetchImage(url: avatarUrl, headers: [:])
let bytes = result.bytes
let pixels = try decodeBlurhash(hash: blurHash, width: 32, height: 32, punch: 1)
```

### Kotlin

```kotlin
val result = media.fetchImage(avatarUrl, emptyMap())
val bytes = result.bytes
val pixels = decodeBlurhash(blurHash, 32u, 32u, 1f)
```

`fetchImage` returns bytes and their source in `ImageFetchResult`. `source` distinguishes a core cache hit, a network fetch, and a local file read. Network fetches use the `Fetcher` and disk cache, with no local HTTP hop. A `file://` URL is read straight from its file and never enters the disk cache. A response above 16 MiB fails. `decodeBlurhash` returns RGBA bytes and throws `MediaError.BlurHash` for a bad string. A loader reports its progress with `media.itemState(key:state:)` so images and audio use the same placeholder chain as video.

### Images outside MediaLayer

A process that cannot open MediaLayer, such as an iOS notification extension or an Android push receiver, loads one image with `MediaImageLoad.load(url:headers:directory:cacheBytes:timeout:fetcher:)` (Swift) or `MediaImageLoad.load(url, directory, headers, cacheBytes, timeoutMs, fetcher)` (Kotlin, `suspend`). The call runs off the calling thread and returns `ImageFetchResult` with `bytes` and `source` (`Cache` or `Network`).

- The core keeps a bounded disk cache in `directory`: the key is the URL, `cacheBytes` is the limit, and the least recently used entries leave first. On iOS pass a directory in the app group so the app and the extension share the cache. On Android pass a directory under `cacheDir`.
- The second load of a URL reads the cache and makes no request.
- No answer within the timeout throws `MediaError.Timeout`. A status other than 200 or a response above 16 MiB throws `MediaError.Fetch` and stores nothing.

The same process encodes image bytes with `MediaImageEncode.encode(bytes:format:quality:limitBytes:)` (Swift) or `MediaImageEncode.encode(bytes, format, quality, limitBytes)` (Kotlin, `suspend`). It gives JPEG or PNG bytes turned upright by EXIF, the same bytes as `encodeImage(bytes:)` of an open MediaLayer, with no proxy, no cache and no MediaLayer.

- The core checks the raster the encode needs (`image_encode_plan` cost) against `limitBytes` before the bytes are decoded. The default is 16 MiB. A size above it throws `MediaError.Overloaded`, bytes that are not an image throw `MediaError.Fetch`.
- The call opens no MediaLayer, no proxy and no background task: all work ends before it returns. Defaults are 8 MiB of cache and a 5 second timeout.

## Closing the MediaLayer

`close()` on Swift (`shutdown`) starts the close and returns at once. The same close starts when the last reference to the MediaLayer goes away, so an app does not have to wait. The MediaLayer stops taking input and `PlayerEvents` first, cancels the assembly and the background work of the sources, disposes every player, then calls `MemoryReleaser.shutdown`. `awaitClosed()` starts the same close if it has not started and returns when all of this is done, so it works on a live handle on both platforms and `close()` after it only frees the handle; cancelling the wait does not cancel the close. Neither your app nor the DSL has to call it. The MediaLayer owns its task executor and ends it after the cleanup, off the calling thread. With a MediaLayer built from parts on an external task executor handle the executor must stay alive until `awaitClosed()` returns.

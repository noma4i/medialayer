# Счётчики вывода видео

`MediaLayer.open(videoOutputCounters = counters)` включает диагностический учёт Android через `VideoOutputCounters`.
Обычное открытие не создаёт счётчики, списки событий, таймеры или диагностический `ForwardingPlayer`.
Счётчики меняются только при работе слота или привязке вида.
`snapshot()` вызывается на главном потоке, поскольку читает `TextureView.isAttachedToWindow`.

| Поле | Значение |
| --- | --- |
| `create`, `release`, `livePlayers` | Создание, освобождение и разность числа ExoPlayer |
| `prepare` | Реальные вызовы `ExoPlayer.prepare`, включая предварительную подготовку |
| `attach`, `detach` | Команды слоту, независимо от изменения вида |
| `repeatAttach` | Повторная команда с теми же slot, key и token без detach |
| `setVideoTextureView`, `clearVideoTextureView` | Вызовы Media3 для вывода кадра |
| `textureCreate` | Число различных TextureView, переданных Media3 за диагностический сеанс |
| `liveTextures` | Из наблюдавшихся TextureView только прикреплённые к окну, без подсчёта удерживаемых отсоединённых объектов |
| `firstFrame` | События `onRenderedFirstFrame`, включая первый кадр после смены вывода |

Отсутствующее поле означает 0 событий.
Счётчики принадлежат одному открытию библиотеки.
Передай новый экземпляр при следующем открытии.
`textureCreate` измеряет объекты Java, не число SurfaceTexture или графических буферов.
Счётчик не доказывает освобождение отсоединённых объектов сборщиком мусора.

`stats().slots.playing` считает слоты с `is_playing || is_peeking` на обеих платформах.
Это число командно активных плееров, не число слышимых плееров или плееров с готовым кадром.
`hot` считает удержание буфера, включая следующую страницу.
Новая соседняя страница получает `Preroll`, восстановленный trimmed-слот получает `Retain`.
Обычная следующая страница не получает `Play`.
Явный `peeking` запускает соседа без звука и учитывается в `playing`.

## Проверка на устройстве

1. Открой диагностическую сборку с одним экземпляром `VideoOutputCounters`.
2. Открой видео-страницу и дождись первого кадра.
3. Сними исходный `snapshot()` и `stats().slots` на главном потоке.
4. Сделай 10 переходов между соседними видео, каждый раз дожидаясь первого кадра.
5. После каждого перехода сохрани снимок, ключ страницы и её номер.
6. На неподвижной странице поменяй mute, сохрани снимок повторно.
7. Проверь неизменность attach, prepare и setVideoTextureView при сохранении player и вида.
8. Закрой страницу и проверь число прикреплённых TextureView.
9. Освободи библиотеку и проверь `livePlayers = 0` после обработки главной очереди.

Включи приложение в `atrace_apps` конфигурации Perfetto.
Секции: `MediaLayer.create`, `MediaLayer.prepare`, `MediaLayer.attach`, `MediaLayer.detach`, `MediaLayer.firstFrame`.
При включённых счётчиках также доступны `MediaLayer.setVideoTextureView` и `MediaLayer.clearVideoTextureView`.
Для чтения сохранённой трассы используй `trace_processor_shell trace.perfetto-trace -q counts.sql`.
Запрос файла `counts.sql`: `SELECT name, COUNT(*) FROM slice WHERE name GLOB 'MediaLayer.*' GROUP BY name`.
Ограничь запрос временным интервалом 10 переходов при сравнении с разностью снимков.

Samsung Android 16 и Android 13 проверяются отдельно.
Проверь 16 dp, alpha, движение pager, первый кадр, возврат назад и отсутствие двойного звука.
Замер JVM не доказывает эти свойства устройства.

## Возможные отдельные эксперименты

Сохранение TextureView за слотом требует одного владельца Android View в каждом моменте времени.
При переносе между страницами необходимо отсоединить прежнего родителя и сохранить правила выбора активного token.
Держать одновременно один View в двух родителях Android нельзя.
Понадобится согласовать повторное использование AndroidView с Compose `onReset` и `onRelease`.
Отсоединение TextureView само может уничтожить SurfaceTexture, поэтому сохранение Java-объекта ещё не доказывает сохранение графических ресурсов.
Альтернатива - стабильный ContentFrame в одном месте композиции с заменой player.
Она не гарантирует один вид между разными страницами pager.
Оба варианта требуют отдельного сравнения create, setVideoTextureView, первого кадра и графических буферов.
Они не устраняют копирование каждого кадра TextureView.

Прототип SurfaceView допустим только отдельно, за флагом приложения, выключенным по умолчанию.
Проверяй тот же набор страниц и повторяй прежний сценарий падения при движении pager.
Проверяй скругление, alpha, перекрытия, возврат и первый кадр на обеих версиях Android.
Текущий вывод видео не переключается на SurfaceView.
